Entrepreneur platform · industry-agnostic · local synthetic-data application

From idea to a governed launch plan.

A launch workspace for any business: a project with its assumptions, research with sources, suppliers with honest verification status, a financial plan, an agent-assisted procurement recommendation, THE WEIR approval and an audit trail. It is exercised here on two synthetic tenants: NASHA — Flagship Hospitality Launch Case Study (a proposed brand, not an operating business) and a fitness studio. Everything below is recorded output of the running application. No supplier was contacted, nothing was ordered, and the supplier prices compared are synthetic fixtures.

      Where the agent fits

      An agent prepares the research. It never decides.

      The Production AI Agent Platform engine runs with read-only tools over one tenant's supplier records and returns a cited brief. Every number in the recommendation is computed from stored quotes and re-derived by separate arithmetic; the agent's claims are checked against those same stored prices, and discarded if they fail.

      • RanThe platform's real engine with its offline heuristic provider: deterministic and extractive, not a language model. If the engine is unavailable the run falls back to a stored-data summary and says so; the recommendation is identical either way (tested).
      • Not runNo language-model provider was exercised. The release gate therefore stays at REQUIRES_REVIEW and this page makes no model-quality claim.

      Is any of this model-backed?

      No language model has run. Here is the boundary that is ready for one.

      The integration path exists: the platform's local-model provider plugs into the same engine. It could not be exercised here, so nothing below claims a model result. What was built is the boundary every agent or model output must cross, and an evaluation that shows what it does with hostile, malformed and unsupported output.

      Engineering architecture

      How a write, and a recommendation, are protected.

      Business and Engineering views read the same records. The database, not the application, refuses an unaudited write.

      Every write

      1. BrowserBusiness and Engineering views over one set of records
      2. HTTP APITenant from the path, role checked, unknown fields rejected, idempotency keys
      3. ServiceDefault deny; the write and its audit row in one transaction
      4. PostgreSQLRow-level security forced; a deferred constraint refuses any change without audit evidence; hash-chained audit under a lock held for the whole read-and-insert

      A procurement recommendation

      1. Stored quotesRead through THE WEIR; supplier information labelled by category
      2. Agent engineRead-only tools; offline heuristic here, a local model possible
      3. BoundaryStructure, grounding, number and price checks, injection and tool refusal; uncertainty computed from records
      4. CalculationCheapest valid quote per ingredient, re-derived by separate arithmetic; the agent cannot change it
      5. THE WEIR holdThe write waits for a different person; the approval is single-use
      6. RecordRecorded, and the project advanced, in the same transaction as its audit row

      Mutation tests for the launch workflow

      Break a control; the probe must notice.

      Eight mutants: claim verification, cheapest-quote logic with its re-derivation, quote validity dates, the stale-proposal check, the audit row, approval single use, the role policy and the supplier-contact rule.

        Honest limits

        What this is not.

        • SyntheticProjects, assumptions, fixtures and prices are synthetic planning inputs. The financial plan is a simulated projection, not business performance.
        • IncompleteThree real suppliers appear only as leads found through public web search: official websites not verified, no contact details stored, no published prices. External verification is incomplete and no supplier was contacted.
        • Not builtNo ordering, payments, supplier contact or marketplace. A commercial product would need real supplier verification, real quotes and operational validation.
        • UnverifiedRemote CI has not run and no language-model integration was tested.
