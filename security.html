Security and governance · recorded synthetic scenarios

What happens when someone tries to buy something they shouldn’t?

Eight scenarios were executed against two synthetic tenants and recorded. These are test scenarios, not real security incidents; there is no production system, no real user and no real supplier. Every number resolves to the recorded evidence.

Reveals the evidence file and pointer behind every number.

THE WEIR and denied actions

Every scenario, and the layer that stopped it.

A purchase needs four independent layers to agree. The approved path ends in a draft order that is never transmitted.

Authorization and approvals

Who may do what, enforced and tested.

Role policy, maker-checker, call-bound single-use approvals and scope tampering.

Cross-tenant isolation

Another tenant’s identity gets nothing.

Separate signing secrets, warehouses, ledgers, approval stores, memory and private documents. Not isolated: one process, shared code and shared reference recipe files.

Audit completeness

Every operation, including refusals, leaves a record.

The ledger audit is hash-chained, so an edited row is detectable.
