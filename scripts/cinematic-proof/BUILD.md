# Reproduce the isolated proof

This is Phase B review work, not a production redesign. See REVIEW.md for scope, baseline, five visual acceptance criteria and the required stop before expansion.

## Assets and dependencies

- `scene.glb`: original local Blender architecture and articulated mechanical VECTRA translation, authored by `build_scene.py`. No downloaded character, stock architecture model, personal likeness, generated photograph or paid asset service.
- The approved VECTRA WebP remains unchanged and is available as a separate reference. The new model does not reproduce the illustration's full detail and is not an approved identity replacement.
- Blender 4.3.2, with its built-in text geometry, was used for the original asset. No source rig existed at the audit baseline. The model uses named object joints rather than an imported skin or skeleton. Only one specialist is modeled.
- Three.js `0.180.0` (MIT) provides the optional renderer, GLB loader, orbit controls and procedural lighting environment. Its license is in THIRD-PARTY-NOTICES.txt and generated notices in graphics.js.LEGAL.txt. esbuild `0.25.12` is build tooling. Exact dependency integrity is in package-lock.json. The dependency audit reported zero vulnerabilities.
- `viewer.js` is a small workflow/loader module. It fetches `graphics.js` and `scene.glb` only after explicit 3D intent. Public production pages do not import this trial renderer.

## Optional asset/code rebuild

The prebuilt source files permit Mac preview without Blender or npm. A developer can rebuild them with:

```sh
blender -b -t 4 --python scripts/cinematic-proof/build_scene.py -- scripts/cinematic-proof/scene.glb
npm ci --ignore-scripts --prefix scripts/cinematic-proof
npm run bundle --prefix scripts/cinematic-proof
```

Review regenerated bytes before replacing a checksum-pinned candidate.

## Build the review artifact

```sh
python3 scripts/build-cinematic-proof.py --out work/my-new-proof
```

The output must not already exist. The builder first checks and independently HTTP-verifies the exact production publication artifact. It places that separately under `baseline/`, then adds only the named proof assets, four shared-model scripts and the approved VECTRA reference. Tooling, Git metadata and private work directories are not copied.

`proof-manifest.json` records every included file's relative path, bytes and SHA-256, plus a deterministic tree digest. It is a review-artifact inventory, not a production release record. The proof launcher independently rehashes the artifact against the externally supplied tree pin before serving.

The final handoff supplies an exact source commit, source archive SHA-256, launcher SHA-256, proof-tree digest and PR number. `scripts/start-cinematic-proof.py` uses the preserved, separately hash-verified preview helper for ZIP safety, verified HTTPS and current-head checks. macOS uses system curl without disabling certificate verification. Loopback is the default; explicit `--lan` binds only private Wi-Fi plus loopback. Directory listings are refused. No tunnel or deployment occurs.

## Checks

CHROMIUM_PATH=/usr/bin/chromium node scripts/test-cinematic-proof.cjs

The existing `test-living-browser.cjs` entry point also runs the proof checks in Chromium and automated WebKit through the unchanged validation workflow. No workflow, environment, branch or publication protection is relaxed. The normal sixteen browser commands and all 48 existing Lighthouse gates remain.

Coverage includes explicit approve/reject, unauthorized actors, role changes without reset, rejection without receipt, normal eighteen-event approval/recovery, idempotent retry, storage/replay, all four architectural views, four viewport widths, loading-failure fallback, no external proof requests, excluded-tooling 404s, Axe, and the articulated work poses without business-state mutation.

Paired motion-pose tests use a controlled browser clock because software GPU rendering can skip narrow wall-clock sampling windows. Rendered poses are actual WebGL output. These tests do not prove animation smoothness, sustained FPS, physical Mac/iPhone Safari, thermal or battery behavior. Those remain explicit owner-device requirements after visual acceptance and final implementation.
