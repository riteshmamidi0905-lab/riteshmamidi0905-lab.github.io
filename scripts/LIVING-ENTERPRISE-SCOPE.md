5. Each existing specialist has an inspectable work record: actual deterministic input, output, tool/stage and audit event. Unexecuted work is shown as IDLE, not fabricated activity.
6. Atrium readability, shared chamber architecture, mounting of approved character artwork and compact discoverable controls improve without removing the 2D/low-power routes. It connects dining/bar/brewing/kitchen/storage/management/courtyard to actual existing workspaces or explicitly conceptual planning. Approved business/menu images remain unchanged. 8. Homepage routes expose headquarters, founder concept, living mission, FDE journey, applied AI and recruiter information. The existing approved portrait guide adds scripted brewery/mission guidance; no new likeness or voice asset is introduced.
9. All inherited tests and publication protections remain. New pure-model and browser tests cover the actual mission; Chromium and available automated WebKit are tested separately from physical Safari. Four PDFs and all approved image bytes must match baseline.

Stop feature development when these criteria pass and the scoped owner review is ready. Any further simulation scenarios, trained models, custom voices, commercial systems or premium rigged assets are outside this scope.

## Chosen architecture

Existing demo hash utility + existing pure inventory model → enterprise-state.js (immutable commands/events, bounded persistence/replay, typed deterministic functions) → enterprise-ui.js (same-tab session, three perspectives, daily ledger, specialist work records) → headquarters scene / founder concept / engineering UI.

Source of truth is the replayable command/event history. No independent random operational animation or duplicate narrative state. Playback controls change only cursor/presentation; meaningful live steps go through the model. Session storage is not a server security boundary: a browser owner can rewrite code or recompute hashes. Production would need authenticated users, durable transactions and independent monitoring.

Original eight-step controls and manual inventory are retained as explicitly separate regression exercises. The public site does not run the separate recorded Python/FastAPI/SQL services. Their existing case-study evidence remains recorded and is not claimed freshly rerun.
