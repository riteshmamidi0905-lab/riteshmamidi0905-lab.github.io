    Architecture

    Business problem

    A simulated operations manager wants policy lookup and sales analysis to inform restock intent, while reserving approval for a different reviewer.

    Customer requirements

    • Expose a finite set of strictly typed tools.
    • Derive permissions and tenant scope from server identity.
    • Bind independent review to immutable persisted intent.
    • Persist execution steps and recover without creating a new business action.

    Architecture decision

    Use fixed specialist functions and an explicit authority boundary. A model is not needed to prove permission, review and recovery behavior.

    Implementation

    ToolRegistry allows read_policy, sales_report and propose_restock. Knowledge, analyst and planner functions record three structured steps. A reviewer actor must differ from the requester. Approval and outbox insertion commit together; execution reads the stored SKU and amount rather than accepting changed arguments.

    Technologies

    • Python
    • Typed tool contracts
    • FastAPI
    • SQLite transactions
    • RBAC
    • Transactional outbox

    Security

    Unknown tools, extra arguments and unauthorized roles fail closed. Reviewer identity is server-mapped and self-review is rejected. Demo identities are public local test doubles, not production IAM.

    Evaluation methodology

    Control tests verify allowlists, schemas, quantity bounds, tenant isolation, independent review, approval replay and durable traces. The demo asserts execution boundaries independently of retrieval quality.

    Test evidence

    • test_tool_allowlist_and_schema
    • test_tool_trace_survives_restart
    • test_self_review_denied

    • test_review_consumed_once

    Measured local results

    • Three named specialist/tool results are persisted.
    • Operator approval returns 403; dispatch before review returns 404.
    • Independent review succeeds; consumed approval returns 409.
    • Run detail survives a new database connection.

    Limitations

    Deterministic orchestration rather than autonomous LLM planning; no distributed worker scheduler, real identity provider or multi-region persistence.

    Business value

    Makes ownership of consequential actions explicit and reviewable. A real deployment should measure reviewer workload, unauthorized-action prevention and exception cycle time; these business outcomes are unmeasured.

    Reproduce the demonstration

    The private engineering package includes executable code, deterministic fixtures, demo commands and transcripts. Public source for this local extension has not been released. This page does not claim that a separate upstream repository is its implementation.

    Walkthrough: establish synthetic input and identity; execute the nominal path; inject the documented failure; inspect validation and persisted audit; retry or restore using the original intent; reconcile the final result. No paid model call is required.
