    Architecture

    Business problem

    A simulated analyst receives inconsistent SKU casing, dollar-valued CSV fields and duplicate imports that could distort reporting.

    Customer requirements

    • Normalize an exact CSV schema and validate all rows.
    • Transform currency using decimal arithmetic and integer cents.
    • Load atomically with tenant-scoped idempotency.
    • Reconcile source counts, units and revenue before reporting.

    Architecture decision

    Reject a bad batch as a whole and make reconciliation explicit. A polished report is useful only when its underlying import is trustworthy.

    Implementation

    The pipeline trims IDs, lowercases SKUs and converts decimal dollar prices to cents. All rows validate before a transactional import. Batch digests detect changed replays. Reconciliation checks accepted IDs against SQL totals; a CTE and window ranking produce the report.

    Technologies

    Security

    Tenant scope is server-derived and SQL parameters are bound. No generated SQL or arbitrary server file path is accepted. Audit events record source digests and validation outcomes, not rejected raw customer data.

    Evaluation methodology

    Tests cover invalid currency, excessive precision, negative values, malformed headers, duplicates, changed payloads and replay. The demo requires the exact accepted-source totals and no mutation after a rejected import.

    Measured local results

    • Synthetic fixture: 3 records, 22 units and 17,200 cents reconcile.
    • Replaying the same batch does not double count.
    • An invalid price returns 422; existing reports remain unchanged.
    • Twenty concurrent duplicate imports in the control test create one non-replayed import.

    Limitations

    Fixed SKU schema and local batch workload; no CDC, Kafka, dbt, Airflow, cloud warehouse or external source-of-truth reconciliation.

    Business value

    Makes data quality and reporting definitions auditable. A real pilot should measure reconciliation exceptions and analyst correction time; no operational improvement percentage was measured.
