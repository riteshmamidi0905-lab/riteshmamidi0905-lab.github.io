## Launch controls

1. Review the isolated branch diff, media contact sheet, disclosures and acceptance evidence.
2. Confirm the development commit's CI is successful, including unchanged baseline checks and new ecosystem checks.
3. Review source-link correctness, mobile readability, keyboard navigation and film captions manually.
4. Check all assets are original or rights-cleared. The local SVGs and captures are project-authored; generated paid imagery remains planned.
5. Obtain explicit approval for the exact production merge/deploy and destination. No deployment or merge is authorized by the development request.
6. Deploy only that approved commit; smoke-test navigation, evidence links and page assets. Roll back by reverting that release commit if needed.
7. Obtain separate approval before posting LinkedIn copy or film. Keep generated/synthetic disclosures in accompanying text.

## Status vocabulary

IMPLEMENTED = present in code. TESTED = stated checks passed locally. CI VERIFIED = a linked run passed at its exact commit. ILLUSTRATIVE = synthetic scenario/design/browser reenactment. PLANNED = future work. NOT VERIFIED = evidence unavailable. Never promote one status to another by inference.
