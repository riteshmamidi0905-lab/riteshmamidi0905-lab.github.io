## Experience map

- A: Command Center → original specialist profiles and role-sequence replay.
- B: Digital Twin → courtyard service, seasonal concept and inventory-pressure fixtures; four keyboard-operable zones; input validation and what-if reset.
- C: THE WEIR → request → policy → ALLOW, DENY or APPROVE → simulated reviewer → exact-request execution → ordered incident records.
- D: Specialist identity → twelve abstract vector instrument portraits with shared composition and original per-role colors. These are interface art, not people or independent LLMs.
- E: Recruiter mode → builder, problem, implementation, evaluation, decisions, limits and source. Entry is generated by `scripts/render.js`.

## Visual tokens and motion

Use existing ink #eaf5ff, cyan #5ee8fa, violet #a78bfa, gold #efc58b, surface #101c30. Added panels use #101e32, muted text #bbccdf and line #4b6582. Use system sans and monospace to avoid new font downloads. Large headings retain the existing clamp scale. Use a 1rem panel gap and 12–18px panel radii. Preserve role colors in `content/nasha-specialists.json`.

The conceptual court is a CSS grid with a perspective grid background, open center and tank-hall emphasis. Source: the engineering repository's pinned historical cultural design research. It is not a current commercial layout, climate model, buildable design or architectural commission. No sacred forms or unlicensed brand assets.

No autoplay is added. Hover motion uses 180ms transitions only under no-preference. Existing replay stays manually controlled. All controls are native buttons, selects and number inputs; layouts collapse below 760px. Aim for 44px control targets and visible focus. Do not communicate state with color alone.

## Acceptance criteria

1. Preserve the original five-width Command Center acceptance, portfolio navigation, evidence hashes and claim guards.
2. Model arithmetic agrees with hand calculations; invalid/nonfinite/negative input is rejected without overwriting the last valid state. Finance explicitly assumes all demand is fulfilled.
3. APPROVE does not forward. Changed arguments fail. A consumed grant cannot be replayed. A new request invalidates a prior illustrative grant. Unknown tools deny.
4. At 1440, 1180, 820, 390 and 320px: no horizontal overflow, failed assets or JavaScript errors; keyboard skip link and original dialog behavior pass.
5. New page interacted and open-dialog states have zero axe WCAG 2.0/2.1 A/AA violations. Automated checks do not constitute a complete manual accessibility audit.
6. Complete new page under 100KiB gzip and CLS < 0.1 in the local browser test; no external requests or added runtime dependencies. These measurements are not a new Lighthouse score.
7. No-JavaScript view retains disclosures, architectural explanation, recruiter summary and source links.
8. CI runs original tests and `npm run test:ecosystem` on the isolated development branch.

## Model boundary

Pure browser models live in `assets/js/nasha-ecosystem-core.js`; DOM interactions in `nasha-ecosystem.js`. There is no backend connection, persistent storage, authentication, real approval token, cryptographic audit chain or external execution. The browser sequence is an illustration, not gateway security enforcement. See pinned `weir_adapter.py` and actual integration tests for implemented Python behavior.
